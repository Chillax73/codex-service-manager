# Spec Delta

## Purpose

让用户按项目控制服务自动发现和已有服务的持续状态检查，减少闲置项目的后台检查。暂停时保留登记、历史及可识别的新鲜度信息，并允许显式刷新或手动控制，不把缓存状态当作最新事实。

## ADDED Requirements

### Requirement: 项目级自动扫描开关
系统 SHALL 为每个项目提供持久化的自动扫描开关；关闭同时暂停该项目的新服务自动登记和已有服务后台检查，默认保持已有项目当前的开启行为。

#### Scenario: 暂停一个项目
- **WHEN** 用户关闭项目甲的自动扫描
- **THEN** 系统停止为项目甲自动发现、登记服务及自动检查其服务的进程、容器和健康状态
- **AND** 项目甲的登记和历史保留，其他开启项目照常检查

#### Scenario: 应用与采集器重新启动
- **WHEN** 已暂停的项目在管理应用或采集器重新启动后再次加载
- **THEN** 项目仍为暂停状态，不因重启默认重新开启

#### Scenario: 没有项目记录的新工作目录
- **WHEN** 系统首次在尚未登记且没有暂停策略的目录发现具有可靠归属的服务
- **THEN** 系统沿用现有自动发现行为，不要求用户逐项目先开启

### Requirement: 所有后台观察入口遵守项目策略
系统 MUST 在所有服务自动登记、观察信息更新及后台状态检查入口遵守项目扫描策略，包括管理窗口关闭时仍在运行的采集器；暂停前发起的工作也不得在暂停完成后提交过期观察结果。

#### Scenario: 暂停时已有待处理采集任务
- **WHEN** 某项进程或容器采集在项目暂停前开始，在暂停保存完成后准备登记或更新
- **THEN** 该工作不得提交新的自动观察记录或刷新该项目的状态缓存

#### Scenario: 暂停期间周期性刷新界面
- **WHEN** 管理应用的刷新计时器运行，或关闭主窗口但采集器继续运行
- **THEN** 暂停项目不产生针对该项目服务的后台身份、Docker 或健康检查
- **AND** 共享采集基础设施仍可为其他项目运行，不改变全局 hooks 的信任或审核状态

### Requirement: 暂停状态与上次检查时间可见
系统 SHALL 在项目、服务详情和相关汇总中展示已暂停自动检查及上次实际检查时间；从未检查时明确显示尚无检查记录，缓存的运行或健康状态不得被呈现为刚刚确认。

#### Scenario: 暂停后服务在外部退出
- **WHEN** 已暂停项目中的服务在外部退出，用户尚未显式刷新
- **THEN** 界面保留带时间的上次已知状态并标记暂停，不宣称该服务已被重新确认运行或停止

#### Scenario: 仅重新绘制界面
- **WHEN** 界面重绘、切换项目或读取缓存列表
- **THEN** 上次检查时间不更新，聚合数量明确区分缓存结果与实时结果

### Requirement: 显式刷新不自动恢复扫描
系统 SHALL 允许用户显式刷新暂停项目中的已登记服务，一次性完成实际检查并更新检查时间；“全部项目”的显式刷新覆盖其已登记服务，但不改变任何项目的扫描开关。

#### Scenario: 用户手动刷新暂停项目
- **WHEN** 用户明确刷新某个暂停项目
- **THEN** 系统只检查该目标项目的已登记服务并更新其缓存及检查时间
- **AND** 扫描开关仍为关闭，后续周期刷新不继续实际检查

#### Scenario: 检查失败
- **WHEN** 显式刷新遇到身份不符或 Docker 不可达
- **THEN** 系统返回真实未知或错误状态，不把错误转成已停止，也不恢复自动扫描

### Requirement: 自动检查随窗口及采集活动调整频率
系统 SHALL 在主窗口可见时约每 2 秒请求快照，关闭、最小化或隐藏时约每 10 秒更新菜单栏，并在重开主窗口时请求刷新。采集器独立于窗口运行。

#### Scenario: 采集器空闲时收到 shell 检查点
- **WHEN** 采集器没有正在跟踪的进程或近期 Docker 事件，正在等待下一轮检查
- **THEN** 采集器通过 FIFO 响应新检查点，无需等空闲轮次间的约 5 秒等待结束
- **AND** 有跟踪进程或近期 Docker 事件时，轮次之间约等待 0.5 秒

### Requirement: 暂停项目的手动控制使用实时核验
系统 MUST 在暂停项目的显式启动、停止、重启和删除之前实时核验相关对象，不以缓存状态代替操作条件；暂停扫描本身不触发启停，也不修改原项目结束策略。

#### Scenario: 缓存显示停止但真实对象仍活动
- **WHEN** 用户试图删除或重新启动一个缓存显示停止、但实时核验仍活动的服务
- **THEN** 系统依据实时结果拒绝删除或重复启动，并解释原因

#### Scenario: 已配置退出或结束策略
- **WHEN** 用户只修改自动扫描开关
- **THEN** 服务的真实运行与既有结束策略保持原状；发生已授权的策略操作时仍重新核验身份

### Requirement: 恢复自动扫描
系统 SHALL 在重新开启项目扫描后恢复该项目的自动发现和已有服务检查，沿用可信身份与去重规则；不通过历史启动事件制造已经结束对象的虚假当前运行。

#### Scenario: 恢复后发现当前仍存活的可信服务
- **WHEN** 用户重新开启扫描且存在仍活动、可确认身份及项目归属的服务
- **THEN** 系统恢复观察并按既有身份去重，刷新真实状态与检查时间

#### Scenario: 只有已经结束的历史候选
- **WHEN** 恢复扫描时旧事件对应的进程已结束且无法核验当前活动对象
- **THEN** 系统不将该事件补记成正在运行的新服务

### Requirement: 已登记项目可批量切换自动扫描
系统 SHALL 提供「全部启用」「全部暂停」及针对勾选项目的启用或暂停。全量操作以执行时已登记的项目为范围；多选操作以明确勾选的项目标识为范围。批量结果一次生效，沿用单项目开关的持久化、缓存和观察代际规则。

#### Scenario: 全部暂停后首次发现新项目
- **WHEN** 用户暂停全部已登记项目，之后首次在一个没有既有暂停策略的工作目录发现满足登记条件的服务
- **THEN** 此前已登记的项目保持暂停，新项目按默认开启自动扫描并沿用可信归属与去重规则

#### Scenario: 全部启用已登记项目
- **WHEN** 用户选择「全部启用」
- **THEN** 系统启用操作时已登记的所有项目，包括置顶项目，并保留各项目的运行与历史记录

#### Scenario: 仅切换勾选项目
- **WHEN** 用户勾选一部分项目并启用或暂停
- **THEN** 只有勾选项目的策略会被设置，未勾选项目维持原有策略，当前浏览的项目及服务保持选中

#### Scenario: 目标变化或提交失败
- **WHEN** 勾选的项目在提交前已被删除，或批量保存失败
- **THEN** 系统保持所有目标原有策略，并提示失败原因

#### Scenario: 批量暂停与后台观察并发
- **WHEN** 系统保存批量暂停后，某个受影响项目的旧自动观察准备提交
- **THEN** 系统丢弃该项目的过期观察结果；显式刷新仍可更新目标缓存，并保留暂停策略
