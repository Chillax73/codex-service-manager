# Spec Delta

## MODIFIED Requirements

### Requirement: 自动检查随窗口及采集活动调整频率
系统 SHALL 在主窗口可见时约每 2 秒读取缓存快照，关闭、最小化或隐藏时约每 10 秒更新菜单栏，并在重开主窗口时立即读取缓存且让后台优先检查已到期的服务。后台按服务类型和活动情况调度状态探测，采集器独立于窗口运行。

#### Scenario: 采集器空闲时收到 shell 检查点
- **WHEN** 采集器没有正在跟踪的进程或近期 Docker 事件，正在等待下一轮检查
- **THEN** 采集器通过 FIFO 响应新检查点，无需等空闲轮次间的约 5 秒等待结束
- **AND** 有跟踪进程或近期 Docker 事件时，轮次之间约等待 0.5 秒

#### Scenario: 界面周期读取状态
- **WHEN** 界面定时读取快照或重开窗口读取快照
- **THEN** 快照读取得到最近状态，不创建每次读取专用的 Python 进程，不同步发起进程身份、Docker 或 HTTP 探测
- **AND** 重开窗口的优先探测请求交给后台处理，不阻塞首屏

#### Scenario: 采集器和管理窗口同时运行
- **WHEN** 同一状态目录的采集器和管理应用都可执行自动检查，且同一服务到达探测时间
- **THEN** 系统合并重复的自动探测，独立的状态探测不会推迟采集检查点响应

## ADDED Requirements

### Requirement: 缓存快照如实展示检查时效
系统 SHALL 使用实际检查时间区分近期结果、过期缓存、从未检查及已暂停。后台不可用时展示可读的上次结果及相应提示。缓存读取不得改变检查时间，实际探测失败必须保留相应的未知或健康异常结果。

#### Scenario: 后台尚未完成首轮检查
- **WHEN** 新登记服务没有状态缓存，或升级后没有可用的旧缓存
- **THEN** 界面显示尚未检查或等待检查，不把缺少数据解释为服务已停止

#### Scenario: 后台暂时中断
- **WHEN** 后台连接断开或已有观察超过时效预算
- **THEN** 界面保留上次可读状态和实际检查时间，并显示状态可能过期，后台恢复后按策略重新探测

#### Scenario: 已有探测结果后切换暂停
- **WHEN** 自动探测在项目暂停前开始，暂停后才结束
- **THEN** 旧结果不得覆盖缓存，之后的自动任务也不探测该项目，直至重新开启

### Requirement: 显式操作和刷新保留实时核验
系统 MUST 对显式刷新按所选项目或全部已登记服务实际探测，并在启停、重启和删除时重新核验目标。界面缓存和后台时效预算不替代操作核验，后台不可用时仍可使用显式操作。

#### Scenario: 暂停项目手动刷新
- **WHEN** 用户点击刷新当前暂停项目
- **THEN** 仅实时检查选定项目，返回实际结果及检查时间，项目保持暂停

#### Scenario: 缓存显示停止但进程仍活动
- **WHEN** 用户根据旧缓存尝试启动、重启或删除服务
- **THEN** 系统以实际身份和状态为准，拒绝重复启动和不满足条件的操作
