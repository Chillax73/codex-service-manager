# Proposal

## Why

管理窗口的周期快照每次都会启动 Python 并探测开启扫描的服务，自动采集还会检查其中一部分。仓库曾在 260 条登记的空闲场景记录到窗口打开时占单核 23.7%，需要在同负载下确认优化是否减少总成本。

## What Changes

- 周期快照复用本地连接，从状态缓存获取数据。窗口打开、仅菜单栏驻留及重开窗口仍按各自的显示节奏更新。
- 后台统一调度已登记服务的到期探测，合并重复工作，并把暂停、未检查、过期和实际探测失败区分开。
- 保留显式刷新范围与启停、重启、删除的实时核验，保持 CLI 列表及显式发现的既有语义。
- 使用相同的 260 条服务数据，对比改造前后的整体 CPU、子进程、写入和状态可见延迟。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-auto-observation`：将界面快照与状态探测解耦，明确缓存时效、调度及后台不可用时的行为。

## Impact

- Swift 数据读取路径与 Python RPC。现有一次性请求继续服务 CLI、显式操作和退出观察器。
- Python 探测入口与自动采集共享调度规则，复用 SQLite 状态缓存。
- 受影响的工程基线、操作说明及性能基准须随行为更新。可靠性修复由独立变更 `harden-service-lifecycle` 处理。
