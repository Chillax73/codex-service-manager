# Spec Delta

## ADDED Requirements

### Requirement: 已删除服务可从本机回收记录恢复
系统 SHALL 在管理设置列出单服务回收记录，包括升级前已留存的记录。恢复必须保留原登记身份、配置及留存历史，并且不启动服务或合并到现有登记。清单不得回传私密环境值。

#### Scenario: 从旧版单服务回收记录恢复
- **WHEN** 原项目仍存在且原登记身份未被占用，用户选择恢复已删除服务
- **THEN** 系统恢复原项目下的服务和留存运行、操作历史，移除对应回收记录
- **AND** 可核验归属的留存日志仍可按原运行查看，恢复不发送启停信号

#### Scenario: 原项目不存在或服务已重新登记
- **WHEN** 用户恢复时原项目已删除，或相同服务标识、已核验的容器身份或 Compose 归属已由现有登记占用
- **THEN** 系统解释冲突，完整保留回收记录和现有服务，不覆盖、合并或重新创建项目

### Requirement: 用户可显式清理已删除服务的留存数据
系统 SHALL 允许用户按删除日期预览和确认单服务回收记录清理。常规历史清理、应用启动和升级均不自动清除这些归档。显式清理只移除选定归档及可验证归属、且无其他记录引用的本机运行日志。

#### Scenario: 确认清理已过保留期的服务归档
- **WHEN** 用户确认清理超过指定保留天数的已删除服务
- **THEN** 系统移除符合条件的单服务回收记录和对应的自有普通日志及滚动文件，并报告清理和跳过数量
- **AND** 较新的单服务归档、项目回收档案、现有运行、源码、容器及卷保留

#### Scenario: 遇到外部路径或清理中断
- **WHEN** 归档含外部路径、符号链接或其他记录引用，或者删除自有日志时发生可重试的错误
- **THEN** 系统保护不属于本次清理范围的对象，分别报告跳过和失败
- **AND** 已进入清理但未完成的归档可以继续清理，且不会被当作完整可恢复的记录展示
