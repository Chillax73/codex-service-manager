# Proposal

## Why

手动登记与自动采集并用时，普通容器可能漏记。本机启动失败可能留下无法操作的登记，退出策略的单项失败不会显示，而已删除服务的历史与日志缺少恢复和清理入口。

## What Changes

- 按可核验的容器 ID 或 Compose 归属去重，让手动登记与自动采集共用同一状态库时仍能正确登记不同服务。
- 在明确没有创建监督进程的情况下结束失败运行，允许用户重试。仍可能存在活动进程时保留身份保护。
- 在设置中单独展示最近一次 Codex 退出策略的结果，列出失败服务并区分跳过原因。
- 增加「已删除服务」入口，兼容旧归档，支持恢复和显式按删除日期清理。
- 把同库去重、启动故障注入、部分停止失败和回收边界纳入常规回归。

## Capabilities

### New Capabilities

- `service-lifecycle`：本机受管服务启动失败的可恢复性，以及退出策略的执行结果与诊断。

### Modified Capabilities

- `project-auto-observation`：为手动登记和自动观察共存补充容器身份去重规则。
- `service-configuration`：为已删除服务补充恢复、冲突处理及本机数据清理规则。

## Impact

- Python 引擎、自动采集、维护命令和 SQLite 中现有的运行及回收记录。
- Swift 退出观察器和管理设置，沿用现有项目退出触发及保留例外。
- 常规 CI 增加隔离回归。真实 Docker 和 macOS 生命周期仍需各自的集成验收。
- 快照读取和探测调度由独立变更 `decouple-snapshot-probing` 处理。
