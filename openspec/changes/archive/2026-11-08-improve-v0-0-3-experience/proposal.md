# Proposal

## Why

旧项目持续参与自动发现和状态检查，用户无法按项目暂停；初始项目侧栏偏窄、项目只能按名称排列且不能置顶，服务列表也缺少运行优先顺序，影响日常查找和管理。本次按已确认的体验需求补齐项目扫描开关、侧栏布局与排序置顶、服务统一排序及改名、删除与配置编辑。

首轮更新后，项目自动扫描仍需逐个切换。服务列表的「更多」同时承载项目操作、全机发现、手动刷新和管理设置，状态筛选也逐项展示 11 个底层运行状态。本轮补充批量扫描管理，按操作范围重排入口，并简化日常查看和筛选。

## What Changes

- 按项目持久化“自动扫描”开关；关闭时同时暂停新服务自动发现和已有服务的后台状态检查，保留显式手动刷新，显示暂停标记和上次检查时间。
- 项目侧栏首次打开采用约 280 点的默认宽度，记住用户调整；窄窗口下仍可访问服务列表和详情。
- 项目栏提供名称、创建时间、运行中服务数量三种排序，支持升序/降序，默认名称升序；项目可置顶/取消置顶，置顶与普通组内部使用同一排序规则，偏好和置顶状态重启后保留，“全部项目”固定最上方。
- 单项目与“全部项目”列表统一按“当前已知运行中优先、首次创建时间从新到旧、稳定 ID 决胜”排序；重启不重置创建时间，旧数据一次性回填并明确其估算来源。
- 服务支持修改显示名称及下一次启动配置。本机进程/任务可编辑启动命令、工作目录、环境变量和健康检查地址；按用户进一步确认，Docker/Compose 支持改名、删除和健康地址，不包含容器重建。名称修改不改变服务 ID 与历史；配置保存不重启或改变当前运行。
- 服务删除前必须实时确认已无活动、停止失败、未知状态或未结束运行，用户先手动停止再删除登记；不创建忽略标记或永久屏蔽，后续符合采集条件时允许重新登记。
- 在项目栏提供「扫描管理」，支持全部启用、全部暂停及多选后的启用或暂停。全量操作覆盖执行时已登记的项目，未来首次发现的项目默认开启。
- 项目栏保留排序、扫描管理和项目行右键入口。选中项目后，服务列表顶部的「⋯」显示当前项目操作，并提供添加、发现和刷新入口。管理设置位于窗口工具栏。发现容器时在弹窗选择归属项目，刷新标签随查看范围变化。
- 服务列表和筛选使用简化状态，健康异常可单独筛为「需关注」，详情和历史保留原始运行结果与健康信息。
- 采集器空闲时降低轮询频率，收到 shell 检查点立即唤醒。窗口不可见时减少菜单栏轮询，快照批量读取暂停服务的状态缓存。
- 为上述能力增加相应的引擎接口、原生入口、持久化迁移和针对性回归验证。

## Capabilities

### New Capabilities

- `project-auto-observation`：单项目和批量自动扫描策略、缓存状态、手动刷新及跨采集入口的一致性。
- `workspace-sidebar`：项目侧栏布局、排序与置顶，以及项目、服务和应用操作的入口分区。
- `service-ordering`：服务列表的稳定排序、简化状态与筛选。
- `service-configuration`：服务显示名称、下一次启动配置、经实时核验的登记删除，以及自动重新登记语义。

### Modified Capabilities

无。当前 `openspec/specs/` 没有主规格，以上为首次引入的 OpenSpec 能力。已有 `specs/001-service-manager/` 仍是需遵守的工程基线，本次不将其复制成另一套完整规格。

## Impact

- `backend/engine.py`：项目/服务迁移，项目创建时间与置顶、排序偏好接口，查询与显式刷新分离，统一服务排序和配置接口，删除核验与事务。
- `backend/capture.py`：项目暂停过滤、既有跟踪与容器采集入口、异步工作提交前复核、保留自定义显示名称，以及空闲调度和按变化保存跟踪记录。
- `backend/adoption.py`、`backend/cli.py`：与既有启动配置、手动控制和 RPC 行为兼容。
- `app/Sources/`：项目扫描管理、工具栏与菜单分区、发现结果的项目选择、服务状态投影及原有的排序和配置入口。
- `tests/`、`docs/TESTING.md`：迁移、跨项目隔离、采集与刷新、排序、配置生效时机、删除和实际桌面验收。
- 延续 SQLite、Python 标准库与原生 SwiftUI/AppKit，不引入新的常驻组件或第三方依赖。
- “0.0.3”是本次体验变更的工作标识。变更从应用版本 `0.2.0` 开始，应用版本以 `scripts/build.sh` 为准。
