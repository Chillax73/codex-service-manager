# P4-02 · 同轮读取和进程探测复用

基线为已部署 P4-01（24a860e；部署记录提交 dac1e2c）。本阶段只实施后端与回归，不替换正式应用或重启正式组件。当前项目 hooks/采集器继续开启，其他 61 个关闭目录保持原集合。P4-03 完整原生窗口/菜单矩阵单独记录，不以本页的组件收益代替完整 CPU 结果。

## 变更与安全边界

- engine.read_context 按线程、状态根、单次观察复用连接，启用 query_only 和自动提交；读查询不保留跨调用事务，写入使用独立连接。嵌套上下文与异常退出恢复前一状态，普通 query/write 也显式释放自有连接。
- 共享停止范围检查一次读取各服务的最新未结束运行，保留暂停项目及其他服务的身份冲突判定，不逐条重开历史运行连接。
- 采集进程表同时读取 PGID，受管服务通过该表核验监督器出生身份和成员，避免逐服务调用 ps。FIFO 检查点的进程表只复用到同一轮采集；监听查询限定本轮跟踪 PID。
- 已登记进程的更新不再查询未使用的 cwd；首次登记仍在变更锁外读取 cwd，锁内重新确认记录和策略。并发删除时延至下一轮重新发现，避免使用错误的 cwd 或在锁内运行外部命令。
- 后台观察批次复用本地 observed 服务的进程、监听、跟踪与归属数据。快照绑定服务与运行完整版本，版本变化回退实时探测；项目策略和最终写入代际保护保留。显式停止/重启不传入展示上下文，仍进行新的范围和出生身份检查。

未引入跨轮 TTL 缓存、降低循环频率或删除历史。容器探测方式及健康超时不变，不声称这次解决了所有 Docker 后台开销。

## 复现与组件测量

新增测试发现：仅开启 SQLite query_only 时，失败的写入可能留下隐式事务，影响后续可见性；已增加自动提交，确认被拒绝写入后仍能立即读取其他连接的新提交。

另一次短试跑显示，三个活动进程时仍有每轮多个 cwd lsof；确认读取结果只在首次登记使用后移除了已登记路径的多余探测。该试跑使用 260 条历史、每场景 10 秒，仅用于完善入口和定位问题，不能作为最终版本性能验收。

共享范围查询在相同 SQLite schema 和终态历史下各预热一次，再测三次进程 CPU；一个无活动事务的 keeper 连接维持 WAL，连接计数覆盖实际读取路径：

| 历史记录 | 原查询 CPU/次 | 新查询 CPU/次 | 原/新连接数 |
| ---: | ---: | ---: | ---: |
| 260 | 96.690 ms | 0.632 ms | 261 / 1 |
| 1,000 | 387.603 ms | 0.986 ms | 1,001 / 1 |
| 5,000 | 1,947.446 ms | 3.539 ms | 5,001 / 1 |

以上是零冲突历史场景；SQL 仍按最新运行筛选，不能声称数据库所有工作与历史量无关。原始数据位于 ignored 的 .test-state/p4-02/queries。

## 回归与门禁

15 项新增测试覆盖：线程隔离、嵌套/失败退出、拒绝写入及无旧事务、暂停项目的共享运行冲突、最新运行选择、PGID 与出生身份复用、监听 PID 交集、同轮后台探测、运行/配置变化回退、显式检查不用缓存、查询失败回退、PID 复用、暂停恢复代际、检查点表复用，以及已有/首次/并发删除情况下的 cwd 读取。

最终实现通过：15 项真实引擎、22 项完整采集（含 Node/Maven）、5 项 shell、9 项候选查询、15 项复用、9 项调度/事件、11 项观察策略、5 项快照缓存、6 项摘要、4 项迁移和 7 项私有存储，共 108 项测试。8 项真实 Docker/Compose 检查通过；只操作独立测试状态、端口及标签资源，原有容器状态不变。最后的 cwd 修改重新运行了受影响的完整采集、候选、策略和复用测试，其余证据来自相同未变代码。
