相邻基线：P4-04 本地提交 `690558f`。先从该提交冻结后端，再实施本阶段。P4-04 真实矩阵中候选 worker 活动窗口中位数为每 120 秒 3,396 次 SQLite 连接、32 次运行更新和 1,478 次观察写入；自身/子进程 CPU 中位数 6.11% / 8.52%，磁盘写入中位数 55,912 KiB。

用 `PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 scripts/benchmark_worker_writeback.py <backend目录>` 对隔离 SQLite 重放已经预热的 12 条到期批次，各重复八次。Docker 探测对象固定，代替外部查询，因而不会把 Docker 或整机 CPU 算进 SQLite 热点。每服务记录写回期间打开的连接，按协调线程及执行线程分列；测试不写正式状态。原始记录留在忽略目录 `.test-state/p4-05/connection-*.jsonl`。

原版每服务写回打开 1～5 个连接；候选复用批次写连接，写回不另开连接。局部重放支持保留 D-05 的范围，不把以上 CPU 差值解释为真实进程收益。工作线程在本批内拥有自己的自动提交只读连接，协调线程使用一只写连接；按 mutation → reconcile → SQLite 的顺序加锁，最终复核、运行协调和观察写入仅用同一事务。旧写者仍可使用原 schema，显式 CLI 继续实时探测。连接和结果绑定状态根与数据库文件身份。

同 ID 服务/项目恢复沿用原登记标识、配置和已有历史，同时推进已有配置/观察代际字段，以拒绝回收前晚到的写回和过时配置提交。恢复回归的字段等价断言保留，其唯一预期差异为版本令牌推进；未新增持久字段。忙锁只保留旧观察，不返回 fresh；读连接不跨线程/数据库复用。六项聚焦测试覆盖真实 SQLite 回滚、已提交其他服务、忙锁及独立旧写者的竞争、去重和新运行、归档同 ID 与根/文件切换。
