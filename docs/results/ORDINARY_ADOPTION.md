# 普通启动后接管验收

日期：2026-10-12（Asia/Shanghai），开发分支，未包含在 v0.1.0 标签。

## 已交付

已有全局观察服务无需重新启动，即可依据出生身份、启动关联和实时树评估停止能力。停止覆盖单项服务的启动器和子进程，逐个复核身份；不向工具 shell 或共享进程组发送信号。共享多监听服务、独立已登记任务、未知子进程或身份不符时拒绝扩大范围。

常见简单 Python HTTP、Node、npm dev/start、npx Vite、Java jar/classpath、Maven Spring 命令可保存结构化启动配置和 PATH/LANG/JAVA_HOME。保留原命令执行行为，不保存整段工具命令、输出、完整环境或聊天。含 shell 运算/展开/重定向/后台符、环境赋值或敏感参数的命令不自动重放。

原生详情提供“配置启动方式…”：历史或复杂启动可补齐单项命令、cwd、显式必要环境。保存保持原运行，已有环境值保留且不在快照中展示。停止和启动/重启分别开放并解释缺少的条件。已有明确容器 ID 的 Docker/Compose 观察成员可控制，容器及数据保留。

重启确认旧树退出及 TCP 监听端口释放后，创建同 service ID 的独立监督运行；新运行开始采集日志。停止失败禁止启动副本，剩余确认范围可显式强制停止。原监听进程退出但启动器仍活着时不开放启动。原观察运行仍排除在项目结束策略之外，经管理器启动后升级为已管理。

## 覆盖边界与清理

仍依赖已加载 hooks 的本机 shell 路径；旧聊天配置加载与无 hook 发现兜底未由本轮解决。不承诺自动拆解任意多服务脚本、守护进程或共享启动器，也不能从 PID/端口还原未采集的启动参数和环境。显式配置必须仅启动目标单项服务。原输出和退出码无法补回；菜单栏复用相同能力，本轮未重新逐项点击菜单栏快捷控制。

测试服务、容器及隔离 UI/采集组件按测试身份清理。正式观察器记录中的测试副本先生成精确归属清单，逐项证明测试 PID/出生身份及已退出状态，再事务归档；保留本机可恢复副本和日志，原有定义显式保护。首次清理自动审批因认为范围可能包含非测试对象拒绝，后续改为明确清单并重查身份后通过，没有绕过审批。正式采集器保留；原业务定义/历史保留，最终运行状态以现场核对为准。
