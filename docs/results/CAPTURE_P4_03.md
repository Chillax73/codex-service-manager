# P4-03 · 启用状态完整对照

状态：功能与完整矩阵 PASS，整体性能门禁 WARN。2026-11-15 完成六轮、24 个场景。实现为 P4-02 提交 e3c9ce4，基线为 P4-01 后端（24a860e，基线目录导出时 HEAD 为 dac1e2c）。本矩阵期间未替换 /Applications，正式采集器未重启；用户随后授权安装，部署证据单独记录。

## 方法与边界

同一台 macOS 主机，同一原生测试驱动，两版后端分别随测试应用打包并校验内容。每轮独立创建 1,000 条合成终态历史，保留正常到期状态回填；四个场景为窗口无活动、菜单无活动、窗口一个实际 HTTP 服务、菜单三个实际 HTTP 服务，各测 120 秒。三组顺序 AB/BA/AB，总计六轮、24 个场景。无活动不等于数据库没有到期工作。

HTTP 服务、原生 GUI 与真实采集器均通过 csm 在独立测试注册表登记；snapshot-worker 是测试 GUI 的实际子进程。HTTP 服务保持监听，不进行业务请求压测。FIFO 输入为明确标记的合成检查点，不冒充桌面真实 hook 回调。正常业务服务不作为负载夹具，不由测试启动或停止。

CPU 为单核 100% 口径，分别统计 GUI、采集器和 worker 的自身与已回收子进程时间，每 30 秒采样一次。RSS/footprint、系统归因写入、SQLite 连接和外部命令次数随场景记录。两版使用相同审计探针，每两秒落盘计数，场景边界存在约两秒误差。温度来自同一组可读核心传感器，仅作整机辅助观察；正式采集器、Codex、浏览器和其他软件仍在运行。

每场景核验快照可读、窗口状态一致、采集心跳正常、历史数量不变和活动服务仍在运行。检查点确认及关联延迟由每个实际 HTTP 服务记录；退出延迟在测量后切回窗口模式，停止自有服务并等待观察结果。不是菜单模式退出延迟的独立测量。

## 测试入口及异常保留

可复验命令见 [测试说明](../TESTING.md)。最终矩阵原始数据在 ignored 的 `.test-state/p4-02/matrix-v3`，包含后端逐文件哈希、逐轮/逐段读数、原生刷新日志及命令计数。整机旁路采样在 `.test-state/p4-02/system-load.jsonl`，仅保存进程名、CPU、负载和温度。组件查询结果见 [P4-02](CAPTURE_P4_02.md)，不与完整 CPU 混用。

初次矩阵的菜单场景出现窗口重新显示，模式断言失败；该轮不纳入比较，原始日志保留在 `.test-state/p4-02/matrix`。没有确认是谁触发重新显示。测试驱动改为持续维持指定模式，两版完全一致，生产 UI 未修改。

第二次矩阵（matrix-v2）续跑后的新版菜单场景末尾仍出现一次窗口显示，模式断言失败，快照读取未失败。随后仅在测试应用增加显示入口的菜单模式保护及明确测试窗口标题，两版重新构建。matrix-v2 的已完成旧版轮次也不混入最终比较，最终矩阵从头测量，保持相同测试驱动。

重跑首轮四个场景和真实服务退出检查完成后，测试 GUI 收尾发生 `[Errno 1] Operation not permitted`，监督器留下 unknown 记录。独立核验确认 GUI、worker、监督器及进程组已不存在，未改写失败登记。原入口同时触发原生退出及 csm stop，已改为先等待原生退出与监督器回收完成；这消除了明确存在的收尾竞态，但不能据此断言权限错误的全部原因。保留有效测量，续跑前校验两版后端哈希及所有前轮进程的实际退出证据。

正式 GUI 在重跑开始前以退出码 0 结束，正式注册表无新增停止/重启操作；无法确认触发方。原正式采集器保持运行。该变化不作为优化效果，最终核验单列。

## 结果

以下为三轮均值，自身及已回收子进程合计；组件合计包含 GUI、采集器和 worker，不包括测试 HTTP 服务及监督器。

| 场景 | 采集器：前 → 后 | worker：前 → 后 | GUI：前 → 后 | 组件合计：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 窗口，无活动 | 0.52% → 0.38% | 5.98% → 4.81% | 3.60% → 2.81% | 10.11% → 8.00% |
| 菜单，无活动 | 0.23% → 0.18% | 0.84% → 0.76% | 0.46% → 0.44% | 1.53% → 1.39% |
| 窗口，一个活动服务 | 19.07% → 13.19% | 15.90% → 6.47% | 3.32% → 2.74% | 38.30% → 22.40% |
| 菜单，三个活动服务 | 27.25% → 13.66% | 11.85% → 1.67% | 0.50% → 0.41% | 39.60% → 15.74% |

采集器活动场景下降 30.84% / 49.87%，组件合计下降 41.52% / 60.26%。本次相邻版本对照没有达到 80% 降幅；原 P4 整体目标也不能用不同负载下的 P4-01 历史结果连乘来证明，仍保留未证实状态。不得把共享范围查询约 99% 的收益当成完整循环收益。

## 环境核验与交付门禁

108 项相关回归、8 项实际 Docker/Compose 检查及构建/签名证据复用 P4-02 相同后端版本。完整矩阵退出码 0，六轮所有服务关联、存活、退出及快照/模式断言通过，所有测试进程和进程组已退出。旧 matrix-v2 的 unknown 清理记录保留，并以独立出生身份和进程组检查确认没有残留。测试入口另外保留启动确认失败时的清理归属，避免遗漏已尝试启动的自有服务。

正式采集器在矩阵期间保持原运行，其他 61 个禁用目录集合未变，当前项目未被禁用；本任务在正式注册表没有业务控制操作。hooks.json 与原哈希一致，实际 hooks/list 确认两个采集钩子 enabled/trusted。整个 config.toml 哈希与早期基线不同，但未保存原内容，无法定位其他配置变化；本任务没有覆盖它。

早期基线的 3 个业务容器在最终核验时已处于 exited，其中一个启动时间也发生变化，触发原因未确认。不能把“本任务未操作业务”写成“整段期间业务状态全部不变”。随后部署以紧邻安装前的实际容器/进程状态建立新基线，保持现状，不擅自恢复业务。

最终矩阵期间旁路采样 107 次，1 分钟负载范围 2.08–7.53；Java、OrbStack Helper、Codex Renderer 的 ps 瞬时峰值分别约 353%、267%、244%，不等于区间平均。四个核心传感器各场景均值约 55.24–70.37°C，最高单点 98.96°C。主机并非空载，温度不支持将变化全部归因于采集器，也不作为单独通过标准。

功能与实测入口 PASS；CPU 有明确收益，80% 整体目标未证实、部分 I/O/退出中位数未改善，整体按 WARN 交付，不扩大宣称。后端代码没有在矩阵期间变化。
