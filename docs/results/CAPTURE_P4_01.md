# P4-01 · 采集候选批量读取验收

2026-11-14。基线为 830df31 的 backend，本轮生产代码仅修改 capture.py。P4-01 功能与回归通过；整体 CPU 降低 80% 的工程目标未达成，保留为后续 P4 风险，不把查询子路径的降幅替代完整循环收益。

## 实现与保护

新增 scope_candidates：没有有效活动跟踪时跳过补全查询；有跟踪时用一次联表查询筛选项目开启、本地 process/task、最新运行 running 且 ended 为空的记录。先解析 runtime 并匹配跟踪 PID/事件，再解析候选 spec。最新运行排序与 engine.latest 相同，保留同时间戳的现有行为。

读取连接在返回候选、执行外部探测之前显式关闭。实际写入仍在 mutation_lock 内复核项目代际、服务和最新运行，停止范围仍经过 stop_plan 的出生身份验证。Docker 关联、心跳、观察队列、0.5/5 秒循环等待和历史保留不变；无 schema、UI 或业务启动行为变化。

修复前失败用例：1,000 条历史、无活动跟踪的 collect_once 打开 2,002 个连接。修复后该轮仅项目读取 1 个连接；活动跟踪存在但无候选时，候选查询恒为 1 个连接，不解码历史 spec/runtime。

## 完整采集循环对照

使用 scripts/benchmark_capture_candidates.py，在本机 Apple M2 上通过 scripts/csm 启动两个版本的真实 collect 守护进程，控制库和数据均隔离。每轮重建 1,000 条已结束 observed 历史和待校正观察缓存；包含正常后台到期回填、心跳与真实 ps/lsof，不用 mock 替代完整循环。活动负载为测试采集器自身的合成 FIFO 检查点；有持续跟踪、没有符合条件的活动本地业务服务。它不等同真实桌面 hook 回调或生产活跃服务矩阵。

AB/BA/AB 三组交替；每轮先预热 5 秒，测无活动跟踪 15 秒，再注入检查点、预热 5 秒，活动测量 60 秒（两个 30 秒桶）。首轮无活动窗口与真实引擎回归末尾有短暂重叠，保留该原始读数；第二、三轮无此重叠，结论一致。正式采集器始终另外运行，不计入测试进程 CPU。

CPU 为 libproc 累计区间差，按本机 Mach 125/3 换算、单核 100%；单列进程自身及已回收子进程，未计监督器或整机其他应用。

| 状态与指标 | 优化前均值 | 优化后均值 | 降幅 |
| --- | ---: | ---: | ---: |
| 无活动跟踪，总 CPU | 15.62% | 1.29% | 91.73% |
| 持续跟踪，自身 CPU | 55.15% | 3.30% | 94.02% |
| 持续跟踪，子进程 CPU | 6.12% | 13.30% | 上升 117.39% |
| 持续跟踪，总 CPU | 61.27% | 16.60% | 72.91% |

旧版三轮活动总 CPU：61.06%、61.50%、61.23%；新版：16.26%、16.46%、17.08%。无活动三轮旧版 16.48%、15.64%、14.75%，新版 1.34%、1.39%、1.15%。活动平均 RSS 31.56 → 30.97 MiB、footprint 27.24 → 21.97 MiB；这些短窗口不证明长期内存稳定性。

六轮检查点均成功确认：旧版 73.84/177.56/87.51 ms，新版 72.84/90.50/82.49 ms。数据不支持精确的尾延迟结论。每轮历史数量保持 1,000、心跳新鲜且无错误，所有测试采集器已停止。

剩余 CPU 主要在已回收查询子进程。循环使用轮末固定等待，单轮数据库耗时下降后，单位时间内可执行更多探测；这可能解释子进程占用上升，尚未用命令计数单独量化。P4-02 应优先剖析、复用同轮 ps/lsof 等读取，保留实际控制前的新鲜检查。本轮未修改该路径或延长轮询来凑指标。

## 查询子路径规模

独立 SQLite 夹具，包含 P3 schema；各路径预热一次、测三次进程 CPU，保留一个无活动事务的连接模拟守护进程 WAL 条件。旧参考路径执行原全量 observed 读取及逐条 service/latest，新路径执行 scope_candidates；均为零候选。此测试在完整循环测量结束后执行。

| 历史数 | 旧路径 CPU/次 | 新路径 CPU/次 | 旧/新候选查询连接数 |
| ---: | ---: | ---: | ---: |
| 260 | 182.257 ms | 0.545 ms | 521 / 1 |
| 1,000 | 697.082 ms | 1.079 ms | 2,001 / 1 |
| 5,000 | 3,482.200 ms | 4.063 ms | 10,001 / 1 |

满足千条历史零候选连接 O(1)、CPU <10 ms 的 P4-01 目标。SQL 仍需筛选历史登记，不声称所有数据库工作与数据量无关。
