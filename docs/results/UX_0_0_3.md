## 原生窗口

| 规格 | 实际结果 |
| --- | --- |
| 项目自动扫描 | 暂停后项目行和详情标记上次检查时间，全部项目显示缓存提示。手动刷新推进检查时间，项目保持暂停。退出应用再打开后，暂停设置和缓存提示仍可见。 |
| 项目栏 | 初始分隔位置为 280 点。拖到 345 点后，折叠再展开、刷新、缩窄窗口及退出重开均保留有效宽度。给隔离偏好写入负值后，重开回到 280 点。 |
| 项目排序与置顶 | 全部项目固定在顶部。切换创建时间和降序后，置顶组与普通组各自排序。取消置顶保留当前选择，改名保留置顶，撤销删除后恢复原组和服务登记。首次删除项目遇到并发操作提示，重新核验后完成。 |
| 服务排序 | 全部项目和单项目都先显示运行中的服务，搜索及状态筛选保留列表相对顺序。重跑后台任务生成新运行 ID，首次登记时间和组内顺序保持。 |
| 配置 | 中文名称立即更新。容器表单显示名称和健康地址，拒绝无效 URL 并保留输入。已有环境值在本机表单中隐藏，过期表单保存被拒绝。新健康地址保存后显示待生效，成功重跑后提示消失。 |
| 删除与重新采集 | 活动服务不能删除，停止或退出后可删除。详情清空，其他项目服务仍显示。再次启动监听同一测试端口的 HTTP 服务，自动采集生成新的登记时间和运行 ID，窗口中重新出现该服务。 |

## 覆盖范围

Docker CLI 指向的本机 OrbStack 套接字不可用，跳过真实 Docker/Compose 容器复验。容器表单使用隔离登记，端点回归覆盖待生效健康地址、发布端口绑定及 Compose 不重建的启动参数。

重新采集通过合成 hook 输入驱动真实采集器和 HTTP 进程。验收结束后已退出隔离应用，并清理该状态目录的采集器、观察器和 HTTP 进程。应用构建版本、正式安装和全局 hook 配置沿用现有设置。
