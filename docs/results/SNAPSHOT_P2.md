# P2 摘要快照与按需详情

周期请求使用 `list-v1` 摘要；选中服务通过只读 `service_details` 获取配置、运行对象和操作记录。配置编辑先读取完整详情，避免用摘要覆盖原命令。摘要携带内容版本，选中项、请求代际或版本变化时拒绝迟到详情。检查时间仍独立更新，日志历史和滚动状态保留。

隐藏窗口使用 `menu-v1`，只传最多 16 条菜单服务及相关项目名称，运行数量和告警来自完整集合。恢复窗口立即补齐列表。旧 `full` API 保留，数据库和日志历史均未清理。菜单生成阶段仍遍历全部缓存，不声称后端工作量已变为常数。

## 回归

- 6 项真实 SQLite/持久 worker 接口测试通过，覆盖摘要字段、详情版本、隐私、全局菜单统计、只读行为及新旧协议恢复。
- Swift Store 测试通过：摘要与详情合并、检查时间覆盖、迟到选择/版本拒绝、菜单隐藏/恢复，以及既有 260/1000/5000 条列表契约。
- 12 类管道读取、5 项快照缓存、14 项真实进程及 10 项配置回归通过。
- 实际原生窗口 7 项检查通过：选中项、历史日志和滚动、手动刷新、worker/数据库短暂不可用与恢复、菜单驻留及重新打开。
- 原生构建与签名通过。接口测试接入 CI；未运行远端 CI。

原生证据：本机忽略目录 `.test-state/native-snapshot-1794627488000247000/result.json`（最终版本比较实现后重跑）。

## 规模与限制

独立单次生成测量（CPU 时间，非驻留占用）：

| 服务数 | 全量字节 | 列表字节 | 菜单字节 | 全量/列表/菜单生成 CPU |
|---:|---:|---:|---:|---:|
| 260 | 543899 | 212509 | 13724 | 5.84 / 6.71 / 5.49 ms |
| 1000 | 2065338 | 790451 | 13353 | 21.41 / 26.08 / 19.32 ms |
| 5000 | 10294539 | 3919651 | 13362 | 98.06 / 132.86 / 100.52 ms |

列表体积减少约 62%，菜单的条目固定为 16；摘要版本计算有额外成本，单次后端 CPU 未改善。原始规模结果保存在 `.test-state/p2-payload-scaling.json`。

## 相邻 CPU 对照

1000 条合成服务、24 项目，同机相同 `-O` 原生构建；正式采集器关闭，测试项目暂停探测。预热后按 P1/P2/P2/P1 四轮各 30 秒，均收到 15 次成功刷新。Mach 时间比例 125/3，单核 100% 口径。

| 轮次 | 版本 | 主窗口 CPU | worker CPU | 刷新中位数 |
|---|---|---:|---:|---:|
| 1 | P1 | 4.32% | 2.40% | 87.34 ms |
| 2 | P2 | 2.54% | 2.95% | 71.18 ms |
| 3 | P2 | 2.66% | 3.04% | 70.45 ms |
| 4 | P1 | 4.87% | 2.76% | 88.81 ms |

均值：主窗口 **4.59% → 2.60%，下降 43.4%**；窗口和 worker 合计 **7.18% → 5.59%，下降 22.0%**。worker **2.58% → 2.99%**，摘要版本生成增加后端成本。刷新中位数均值 **88.07 → 70.81 ms**。每次响应 **2065369 → 790482 字节**，减少 61.7%。

最初实现只减小响应、仍深度比较字典，窗口 CPU 没有改善。最终摘要内容版本覆盖业务字段、登记时间和策略，界面使用版本加新鲜度比较，解决了这项回退。早期 `.test-state/p2-cpu-*` 数据仅用于排查，最终窗口结果为 `.test-state/p2-accepted-window/results.json`。不把各阶段不同时间的基线直接相减；这里比较同一轮重测的相邻版本。

菜单模式另做 P1/P2 各 60 秒，预热至少 3 次隐藏刷新，每轮测得 5 次刷新：界面 **1.75% → 0.52%**，worker **0.46% → 0.60%**，合计 **2.21% → 1.12%（下降 49.4%）**。响应 **2067393 → 13386 字节**，条目 **1000 → 16**；刷新中位数 **177.32 → 48.95 ms**。结果为 `.test-state/p2-accepted-menu-60/results.json`，仅一组相邻比较，不宣称长期统计显著性。此前 30 秒菜单试跑因有效刷新样本不足被测试拒绝，已清理测试应用并重跑，不纳入结论。

自审额外修复了完整手动刷新不能合并旧详情运行对象的边界，增加回归并重新构建；该选择路径不参与未选中服务的窗口 CPU 负载。最终菜单对照和最后一次原生检查包含此修复。正式 hooks、62 个关闭目录和采集器 19 次历史运行均保持不变；此阶段尚未替换正式应用。
