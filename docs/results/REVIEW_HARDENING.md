## 优化后性能基线

每个数量各采样三次，中位数；同一轮逐步增加真实受监督的无端口休眠任务。CPU 以毫秒计，可因并行跨核而大于墙钟时间，不是整个应用的 CPU 使用率。

| 任务数 | 引擎 snapshot 墙钟 | 真实单次 JSON RPC 墙钟 | Python CPU | 快照查询子进程 CPU | 外部查询/快照 |
|---:|---:|---:|---:|---:|---:|
| 5 | 20.35 ms | 82.38 ms | 22.39 ms | 7.73 ms | 5 次 ps |
| 20 | 48.29 ms | 99.34 ms | 60.75 ms | 29.76 ms | 20 次 ps |
| 50 | 103.29 ms | 163.65 ms | 147.28 ms | 72.32 ms | 50 次 ps |

探索性优化前测量在 50 项时出现秒级开销，并定位出每个监督器每秒约十次全进程组查询。移除无停止请求且主进程存活时的扫描后，仍保持原停止/退出路径的成员核验和 0.1 秒请求响应轮询。前测存在构建/其他负载干扰，不据此宣称严格的加速倍数。

本表不含监督器、已安装采集器等后台进程的总 CPU，也不代表容器/HTTP 健康检查性能。保留现有两秒 UI 轮询与单次 RPC；若复杂场景实测再次超出刷新预算，再考虑分级采样或常驻 IPC。
