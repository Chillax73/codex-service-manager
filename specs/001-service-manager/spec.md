# 001 · 本机服务管理

状态：配套完整控制已验收；用户级自动观察的常见新聊天路径已实施并在本机启用。“任意聊天”目标尚未全部完成，旧聊天及发现兜底见待办与 acceptance.md。需求基线：[PROJECT_REQUIREMENTS.md](../../docs/PROJECT_REQUIREMENTS.md)。

## 用户流程

1. 目标是在任意本机 Codex 聊天启动服务后自动进入项目列表，不要求逐项目配置或逐次登记。当前已验证安装、审核并加载 hooks 的新聊天常见 shell 路径；旧聊天未加载 hooks 时仍会漏记。配套启动入口继续提供完整的启停、重启与日志能力。
2. 菜单栏随时查看运行数量；主窗口按项目搜索服务，分别查看运行与健康状态。
3. 对本机服务、任务、Docker、Compose 成员/组执行启停、重启/重新执行，查看日志与历史。
4. 项目分别选择手动结束、退出 Codex、两者、持续运行；服务可例外保留。
5. 关闭管理窗口仍保留菜单栏；界面重开后核对真实身份。管理界面退出不会停止服务。

## 实施默认值

以下是本次实施采用的可调整选择，不冒充先前用户逐项确认：

- macOS 13+、当前验收 Apple Silicon macOS 15；原生 SwiftUI/AppKit。
- 项目按规范化 cwd/worktree 隔离；默认手动结束开启、退出触发关闭。
- Codex 退出指指定桌面应用的最后一个实例终止。窗口/聊天事件不触发。OS 终止通知无法区分普通退出/强制退出，两种均按“进程已终止”处理，界面说明该边界；Mac 关机不保证完成操作。
- 管理窗口关闭继续管理；管理应用退出服务保留，独立退出观察器继续工作。不开机自动启动。
- 刷新 2 秒，HTTP 超时 1 秒。本机进程正常退出等待 5 秒；超时保留并提示显式强制停止。容器使用 Docker 原生 stop（5 秒超时，由 Docker 完成超时后的终止），保留容器与数据；引擎拒绝停止时禁止继续重启。
- 每次运行日志 1 MiB，2 个滚动文件；历史默认不自动删除，可按保留天数清理已结束记录。
- 服务配置仅保存 PATH/LANG/JAVA_HOME 和显式传入环境，数据目录 0700、文件 0600，UI 不展示环境值。不要收集聊天正文。
- 用户于 2026-10-12 确认分阶段实施：先自动显示服务，再补齐复杂脚本的重启能力。首阶段自动观察对象禁止启停、重启及项目结束策略，界面明确标识“自动观察”；不把观察对象冒充已接管对象。
- 用户级 PreToolUse 接入须经 Codex 正常信任审核。记录执行 shell 身份、聊天/工具标识及工作目录，不读取聊天正文或完整环境。监听进程分别显示；无监听端口的持续任务在持续 30 秒后显示。短暂构建子进程不当作服务。
- 只依据实际启动上下文和进程出生身份关联对象；不能仅凭端口新增或启动时间认领无关进程。采样未捕获的短暂父进程、未启用 hooks 的执行路径和远端执行必须明确说明，不能声明已经覆盖。

## 普通启动接管（2026-10-12，用户要求实施）

- 全局观察对象按实际能力分别开放停止、启动、重启和强制停止；已有对象无需重新启动即可评估停止能力。
- 停止前核对出生身份、已采集启动关联及实时进程树，覆盖单项服务的启动器和子进程；共享启动器、多服务范围、未知子进程不能隐式停止。不得向业务 shell、无关进程或共享进程组发送信号。
- 新启动的简单 Python HTTP、Node、npm/Vite、Java/Maven 命令可保存经保守解析的结构化 argv，保留原 shell 执行行为。只保存必要配置及 PATH/LANG/JAVA_HOME，不保存整段工具命令、完整环境或聊天。
- 对复杂/历史启动提供单项启动配置入口，补充命令、工作目录及显式环境。没有可重复配置时仅开放可靠停止，并展示原因。
- 重启确认旧进程树退出及端口释放后由监督器启动新运行，沿用服务身份和历史；停止失败不得启动副本。
- 手动停止能力不自动加入项目结束策略；经管理器启动后的运行才按已管理服务处理。容器依据已确认身份开放控制，保留容器及数据。
- 真实进程集成、原有回归、重新构建和实际窗口分别验收；合成 hook 输入不视为真实桌面回调。

## 必须保持的规则

- 稳定 service ID、独立 run ID；先停后启；停止失败不启动新副本。
- 进程/健康分离；身份不符、组件不可达必须未知/不可控制。
- 仅管理明确登记对象，进程 PID 与出生时间及监督 token 都需验证。
- 项目策略只影响归属项目；保留例外优先。Compose 组/成员操作去重。
- Docker 控制不删除容器、镜像、卷；关闭窗口不结束工作。
- 同一时间只能对服务执行一次变更；操作逐项持久化成功/失败/跳过。

## 自动观察验收与剩余范围

| 编号 | 场景 | 完成条件 |
|---|---|---|
| G-01 | 用户级接入与新聊天 | 保留其他 hooks，正常审核两个 handler；无项目指令的新桌面聊天触发真实工具事件并登记正确项目。 |
| G-02 | 常见进程启动 | 直接/exec、脚本多服务、nohup 返回及持续无端口任务自动显示，短暂非监听子进程不登记。 |
| G-03 | Docker/Compose | 依据工具返回 ID 或启动配置与实际标签关联；去重、运行历史与只读能力正确，未关联容器不认领。 |
| G-04 | 身份与恢复 | 相同观察幂等、与配套入口去重；PID 出生身份变化不能沿用运行，新运行独立保存。 |
| G-05 | 只读界面与控制 | 列表/计数/筛选包含观察对象；首阶段禁用控制；本轮改为独立能力与原因，可靠手动控制开放，原运行结束策略继续跳过。 |
| G-06 | 独立组件 | 实际设置显示心跳/故障并可恢复；退出管理应用后采集器独立存活。 |
| G-07 | 安装、隐私与回归 | 安装/移除只改本工具条目；不保存原始命令、输出、完整环境或正文，保留业务输出/退出码。 |
| G-08 | 安装前已打开的旧聊天 | 同一旧聊天后续真实工具调用进入采集，不以新窗口或独立配置探测代替验收；正常配置重载路径需实测。 |
| G-09 | 未触发 hooks 的发现兜底 | 后台发现候选对象并展示真实状态；来源/归属不明时保留候选，不伪造 global_hook 来源，不误认领无关服务。 |
| G-10 | 复杂脚本的控制能力 | 在明确归属、完整且必要的启动配置和安全控制方式齐备后升级管理能力；先停后启，停止失败禁止重启。 |

G-01 至 G-07 的结果各有覆盖边界；G-08、G-09 尚未实现或验收；G-10 的常见路径及显式配置接管见本轮 C01–C04，任意复杂包装不作通用保证。自动观察不负责让业务进程脱离原工具生命周期，也不会补回启用前的日志、退出码或运行历史。

## 状态辨识（2026-10-13）

- 列表、详情、运行历史及菜单栏显示一致的颜色与状态图标，保留中文状态文字，不能只凭颜色辨认。
- 运行中/成功/健康可用为绿色；已退出/已停止/失败/停止失败/健康不可用为红色；启动中/停止中/检查中/未知为橙色；未运行/已取消/未配置检查为灰色。红色已退出/已停止表示当前未运行，不改写为失败。
- 运行与健康分别标注，选中行和浅深色模式下仍清晰可读；保持既有状态判断及控制能力。
- 状态筛选支持所有运行状态逐项选择，并保留全部/需关注汇总；逐项筛选按真实状态精确匹配，与当前项目和搜索词同时生效。
- 项目栏按全部所属服务汇总状态及服务总数：有运行中服务显示绿色“运行中 N”；否则依次展示启动中、停止中、停止失败、未知、失败；静态状态相同时沿用该状态，不同静态状态显示“无运行”；没有服务显示灰色“无服务”。存在失败、停止失败、未知、健康不可用或诊断问题时另外显示橙色“需关注 N”，不能被运行中状态掩盖。汇总不受搜索或状态筛选影响。

## Hooks 使用说明补充

README 应区分项目配套完整控制、用户级自动观察和 validation/ 事件实验；退出策略依赖原生观察器。提供安装、信任审核、配置探测、实际事件核验、移除及旧聊天漏记的排障步骤，不能声称安装 hooks 即接管任意服务，或把 SessionEnd 等同应用退出。

## 项目管理可用性（用户确认）

- 支持修改项目显示名称；规范化 cwd、项目/服务身份、结束策略和运行历史保持不变。名称去除首尾空白，1–100 个 Unicode 字符，不含控制/不可见格式或换行字符；同名显示允许，目录区分身份。
- 支持删除项目登记，带明确确认与服务/历史数量预览；将项目、服务、运行历史和对应操作记录移出当前列表，存入本机回收记录，支持撤销与管理设置中恢复。本机日志文件保留，不删除源码目录、容器/卷，也不触发服务停止。
- 用户选择：有运行、停止失败或身份未知的服务时拒绝删除；先由用户手动处理。后端每次删除前重新核对，不能只依赖 UI 的旧快照。
- 项目右键和当前项目菜单均提供入口。删除后清理失效选择与详情；重命名失败保留输入并提示原因。

- 恢复不启动服务；同目录或登记标识已存在时拒绝覆盖，失败保留回收记录。回收摘要不包含服务环境值。
